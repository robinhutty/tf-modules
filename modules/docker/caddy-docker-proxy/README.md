# Caddy-Docker-Proxy module

The basic idea of this module is to use a [TF Provider for docker][10]:

1. To provision containerized [Caddy][11] and appropriate networking so that
2. the Caddy-Proxy will listen to docker events and
3. then automatically configure itself to proxy request to any new application container with the correct `labels`.
4. There are two intended approaches to use this (although there are other possibilities):
    1. Usage via `docker compose`[^compose], e.g.:

        ```yaml
        services:
            whoami:
                image: traefik/whoami
                networks:
                    - tf-network
                labels:
                    caddy: whoami.example.com
                    caddy.reverse_proxy: "{{upstreams 80}}"

        networks:
            tf-network:
                external: true
        ```
    2. Usage with containerized services that are provisioned and configured using the [TF Provider for docker][10]. E.g.:

        ```hcl
        resource "docker_network" "cdp" {
            name   = "tf-network"
            driver = "bridge"
            ipv6   = true
        }

        resource "docker_image" "whoami" {
            name = "traefik/whoami"
        }

        resource "docker_container" "whoami" {
            image = docker_image.whoami.image_id
            name = "whoami"
            networks_advanced {
                name = docker_network.cdp.name
            }
            labels {
                label = "caddy"
                value = "whoami.example.com"
            }
            labels {
                label = "caddy.reverse_proxy"
                value = "{{upstreams 80}}"
            }

        }
        ```


## Usage notes

- Tested using Debian 13 on linux/amd64 and linux/aarch64 (Raspberry Pi4).
- Any composed Service that has a `label` prefixed with `caddy` [will be converted into a Caddyfile config][].
